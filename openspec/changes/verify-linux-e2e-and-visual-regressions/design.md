# Design

## Context

现有 Playwright 已区分功能与视觉项目，并提供 Linux Chromium 配置和快照。剩余风险集中在 CI 环境漂移、快照更新审查和失败产物分散，设计需要在不合并两类测试的前提下加强可诊断性。

## Goals / Non-Goals

**Goals:**
- 在 CI 中显式验证 Linux Chromium、字体、视口和缩放基线。
- 统一功能与视觉失败产物的目录、保留策略和报告链接。
- 保证快照只能通过显式更新流程变更。

**Non-Goals:**
- 不引入第二套浏览器测试框架。
- 不将本地 macOS 渲染结果作为 Linux 基线。

## Decisions

1. 使用 Playwright project 配置中的声明值作为唯一环境基线，并在 global setup 或 CI 前置脚本输出并校验版本；相比仅依赖 CI 镜像标签，这能发现浏览器和字体隐式升级。
2. 功能和视觉项目继续独立执行与上传，产物路径包含项目名、浏览器和测试重试信息，便于定位并行任务的失败。
3. 默认开启失败 trace/截图，视觉失败额外保留 actual/expected/diff；快照更新只允许专用命令执行并要求评审。
4. 对环境漂移使用明确错误码和摘要，避免把基础设施故障误判成页面回归。

## Risks / Trade-offs

- [固定环境校验增加 CI 前置时间] -> 只读取版本和字体摘要，不重复启动浏览器。
- [产物体积上升] -> 仅保留失败重试和视觉差异，按 CI 保留策略清理。
- [字体包缺失导致全量失败] -> 在镜像构建和前置校验阶段尽早发现并给出安装来源。

## Migration Plan

先在 CI 增加环境摘要和失败产物校验，再运行现有 Linux 视觉项目生成一轮基线报告；确认无漂移后启用合并门禁。回滚时可暂时关闭新增校验步骤，但保留原有功能/视觉隔离与快照保护。
