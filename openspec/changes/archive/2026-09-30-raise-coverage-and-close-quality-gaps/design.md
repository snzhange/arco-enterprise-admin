# Design

## Context

当前 Vitest 使用 V8 覆盖率，报告纳入 `src` 业务代码并排除生成客户端、入口、mock 和测试基础设施；最新可信基线为 Lines 72.46%、Branches 72.03%，但全局门槛仍为 33%/42%。核心业务测试已覆盖用户、角色和工作台，低覆盖主要集中在 `pages/official`、`SettingsDrawer`、布局辅助能力、权限/404 展示和剪贴板工具。契约检查通过，但 Orval 运行时产生 `import.meta` target 警告。

## Goals / Non-Goals

**Goals:**

- 让全局和核心目录门槛能阻止真实回退。
- 以用户可观察行为补齐正式支持页面和基础组件的关键边界。
- 让覆盖率报告、产品范围分类和契约校验输出可审查。

**Non-Goals:**

- 不追求所有展示代码逐行达到 100%。
- 不把视觉回归重复改写为大量单元测试。
- 不修改业务 API、认证授权语义或自动生成客户端内容。

## Decisions

### 分阶段提高门槛

首期以当前报告留出小幅波动空间，例如全局 Lines 70%、Branches 68%，随后按目录分别收紧。选择渐进提高而非立即设为当前值，是为了避免测试执行环境或依赖升级造成无意义阻塞；每次提升都必须保留基线报告。

### 以风险边界选择测试

优先测试写操作、权限、错误恢复、输入校验和浏览器能力失败。页面的静态布局与细节由现有 Playwright 视觉项目负责，行为测试只验证用户可观察结果和请求契约。

### 显式分类示例页面

逐页确认 `src/pages/official` 中哪些路由属于产品正式支持范围。正式页面纳入行为测试和覆盖率；展示型示例使用明确分类和既有视觉验证，避免通过无理由排除源代码掩盖缺口。

### 契约检查沿用当前生成流程

保留 OpenAPI 校验、Orval 生成和零 diff 检查，只调整检查运行时的 TypeScript/Vite 模块目标或警告过滤边界，使合法 `import.meta` 不被错误上下文报告；真实 OpenAPI 和生成差异仍然失败。

## Risks / Trade-offs

- [门槛提升造成短期 CI 失败] -> 先以全局门槛和目录基线分阶段提升，并上传报告定位缺口。
- [官方示例页范围判断不一致] -> 在页面清单和页面开发指南中记录正式/示例分类及验收方式。
- [测试过度绑定实现] -> 测试只断言可见状态、交互结果和请求 payload，不断言内部组件树。
- [警告调整隐藏真实问题] -> 只消除可复现的 target-context 警告，保留 OpenAPI、生成 diff 和 typecheck 硬门禁。

## Migration Plan

1. 固定当前覆盖率基线和正式页面分类。
2. 补齐低覆盖高风险模块，确认新测试在隔离环境运行。
3. 提升全局和目录门槛，更新 CI 报告 artifact。
4. 调整契约检查上下文并验证零 diff、typecheck 和 CI 输出。
5. 若门槛导致非预期阻塞，回退单次门槛提升，不回退测试和报告基础设施。
