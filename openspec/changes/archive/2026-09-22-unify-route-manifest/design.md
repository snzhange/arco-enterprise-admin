# 设计

## 上下文

当前页面加载器和路由树集中写在 `src/app/routes.tsx`，菜单与面包屑元数据写在 `src/app/navigation.tsx`，权限守卫又通过 `src/app/route-permissions.ts` 按 pathname 查表。三者共享同一组页面，但没有共享数据结构，因此菜单和直接访问已经出现权限漂移。现有应用还依赖 React.lazy、Suspense、会话保护布局、Arco 菜单状态和 `canAccess` 权限 helper；这些运行时边界需要保持不变。

详见 `proposal.md` 的动机，以及 `specs/route-manifest/spec.md` 的行为要求。

## 目标与非目标

**目标：**

- 建立一份静态、类型安全的 route manifest，覆盖当前全部公开入口、重定向入口、受保护页面、分组和隐藏页面。
- 让路由渲染、菜单过滤、当前导航上下文、面包屑和页面权限守卫从同一条路由记录读取元数据。
- 以现有 `route-permissions.ts` 的模块权限为迁移基准，修复两个已知漂移，同时维持现有菜单顺序和 URL。
- 为结构校验、权限矩阵、隐藏路由、面包屑开关和兼容性行为提供可重复的单元及 E2E 验证。

**非目标：**

- 不引入服务端动态路由、文件系统扫描、代码生成、Umi 或新的路由运行时。
- 不改变权限代码、角色/数据范围模型、后端鉴权或 API 错误语义。
- 不把页面内容、数据请求或表单行为抽象进 manifest，也不重写官方示例页面。

## 决策

### 使用静态可区分的 manifest 类型

定义应用层的路由类型集合，至少区分页面记录、重定向记录和公开入口；页面记录包含绝对路径、懒加载入口，以及可选的标题 key、分组 key、图标、权限、`menu` 和 `breadcrumb` 元数据。分组记录包含顺序、标题、图标、可选权限和叶子页面列表。

路径以现有 URL 形式保存（以 `/` 开头），渲染到嵌套路由时统一去除前导斜杠。这样测试、导航和守卫比较的是同一个规范化路径，避免相对路径和绝对路径混用。

选择可区分类型而不是一组可选字段，是为了让重定向和页面加载器不能被误当成普通菜单项；TypeScript 在新增路由时也能要求必要字段。公开登录页、根路径/仪表盘重定向和 catch-all 404 仍由顶层路由组合处理，其中 404 不进入菜单记录。

### 将懒加载入口保留在 manifest 边界内

继续使用现有 `React.lazy` 语义，在 manifest 外提供小型 `lazyNamed` 适配器，负责把命名导出转换为默认组件。manifest 只保存已包装的加载入口或等价的加载函数，路由渲染器统一包裹现有 `LazyPage` fallback。

这样可避免每条记录重复 `.then(module => ({ default: module.X }))`，又不会引入目录扫描或改变首包拆分。页面模块仍由页面自身导出，manifest 不理解 DTO、查询 hook 或页面内部状态。

### 让三个消费者共享同一条叶子记录

提供少量纯派生 helper：

- 将 manifest 叶子记录展平为路径索引，供路由渲染和守卫按匹配记录取值。
- 根据用户权限同时评估分组和叶子要求；分组和叶子都存在时使用逻辑 AND。
- 过滤出可见分组和菜单项，并按 manifest 声明顺序返回。
- 按规范化 pathname 查找当前分组和叶子记录，供选中态和面包屑使用；`menu: false` 记录不出现在菜单列表中，`breadcrumb: false` 记录不生成面包屑。

`navigation.tsx` 可以保留为这些 helper 的兼容导出层，避免 `AppLayout` 一次性承担 manifest 细节；旧的 `navigation.types.ts` 仅在没有调用者后删除或改为从 manifest 类型导出。路由守卫接收匹配的叶子记录，不再调用独立 pathname 权限表。

### 保留现有路由组合与布局边界

顶层继续按以下顺序组合：公开登录页、会话保护布局、应用布局、受保护页面/重定向，以及最后的 404。受保护页面由统一渲染器生成 `LazyPage` 和权限内容，`ProtectedLayout` 继续负责会话查询与未登录重定向，`AppLayout` 继续负责侧栏、折叠状态和用户菜单。

`/welcome` 作为会话保护范围内的隐藏页面记录，不加入侧边菜单；它不额外引入新的 feature permission，以保持当前从用户菜单进入的行为。结果页保留 `breadcrumb: false`。`/list/search-table` 和 `/user/info` 的叶子权限改为分别使用 `list:read` 与 `user:read`，并与直接访问守卫共享。

### 以纯结构测试加少量浏览器回归验证一致性

manifest 单元测试直接检查路径唯一、菜单项可解析到页面、分组/叶子权限矩阵、隐藏和面包屑字段；测试使用现有 `CurrentUser` 形状和权限 helper，不构造新的 RBAC DTO。必要的路由渲染测试验证重定向、访问拒绝和懒加载 fallback。

E2E 保留当前管理员全量导航和 operator 受限路由场景，并补充两个最小权限用户场景，验证菜单与直接 URL 同时可用。视觉、折叠和菜单顺序断言沿用现有选择器，避免把本 change 扩展成页面重构。

### 被考虑但不采用的替代方案

- **保留三份配置，仅增加 lint 检查：** 只能发现漂移，不能消除重复事实来源，故不采用。
- **使用 React Router 自带 route object 作为唯一模型：** 会把菜单、面包屑和权限字段塞进路由渲染结构，且难以表达不渲染为页面的菜单分组；采用独立 manifest 并由路由适配器消费。
- **按目录自动扫描页面生成路由：** 会引入隐式约定和构建时复杂度，与当前显式页面控制边界冲突，故不采用。

## 风险与权衡

- [路径规范化错误] → 统一要求 manifest 使用绝对 URL，路由适配器集中处理嵌套路由前导斜杠，并为所有叶子路径增加唯一性测试。
- [分组与叶子权限 AND 语义改变现有可见菜单] → 以当前模块权限为基准迁移，增加 admin、operator、最小权限用户矩阵和两处漂移回归测试。
- [懒加载组件类型或循环依赖] → 将 `lazyNamed` 与纯 manifest 数据放在独立模块，路由文件只负责适配渲染，不让页面模块反向导入 manifest。
- [隐藏路由被错误加入菜单或面包屑] → 对 `menu: false` 和 `breadcrumb: false` 建立结构测试，并保留 `/welcome`、结果页 E2E/渲染断言。
- [菜单顺序、展开态或移动断点回归] → 保留现有数组顺序、`AppLayout` 的状态逻辑和选择器，迁移后执行现有 typecheck、lint、unit、build 与 E2E。
- [旧导出被外部代码依赖] → 先以兼容导出层迁移消费者，确认无调用者后再删除 `route-permissions.ts` 或重复导航类型。

## 迁移计划

1. 新增 manifest 类型、懒加载适配器、静态记录和纯派生 helper；先为路径与权限规则建立单元测试。
2. 将路由渲染和守卫切换到 manifest，保留现有会话保护、布局、重定向、404 和加载反馈。
3. 将菜单、当前分组/项和面包屑切换到同一 manifest，校正两个漂移权限并补充最小权限 E2E。
4. 删除已经没有调用者的独立 pathname 权限表和重复类型，更新必要的 README 目录描述。
5. 执行完整验证命令并在变更分支提交结果；本 change 不涉及数据库或后端迁移。

回滚时按提交粒度恢复路由和导航消费者即可；由于 manifest 只存在于前端静态代码，回滚不需要数据修复或 API 版本协调。

## 待决问题

无。当前页面导出名称、权限基准、隐藏路由语义和兼容性边界均可由现有代码与清单确定。
