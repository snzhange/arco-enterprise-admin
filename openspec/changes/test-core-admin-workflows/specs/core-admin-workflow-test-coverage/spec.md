# Spec Delta

## Purpose

为角色、用户、设置和工作台建立以用户可观察行为为中心的测试边界，使核心后台操作在错误、权限和恢复路径上具备快速回归能力。

## ADDED Requirements

### Requirement: 角色权限编辑行为必须可验证

测试 SHALL 覆盖角色目录加载成功、失败和空状态，读写权限边界，权限草稿的修改/取消/保存，以及未知权限和通配权限的保留或保护。失败保存 SHALL 保留未提交草稿。

#### Scenario: 只读角色页面不可保存

- **WHEN** 用户拥有 `roles:read` 但没有 `roles:write`
- **THEN** 测试 SHALL 证明权限内容可见、保存操作不可用且不会发起更新

#### Scenario: 未知权限保存时保留

- **WHEN** 角色包含权限目录中不存在的代码，用户修改其他权限并保存
- **THEN** 测试 SHALL 证明未知代码仍在提交内容中

#### Scenario: 保存失败保留草稿

- **WHEN** 角色更新返回 403、400 或网络错误
- **THEN** 测试 SHALL 证明编辑内容仍可见，用户可以重试或取消

### Requirement: 用户管理关键操作必须可验证

测试 SHALL 覆盖用户列表的加载/空/错误/403 状态、详情、新增、编辑、字段错误、保存成功、筛选分页上下文和无写权限行为。失败提交 SHALL 保留抽屉和未提交字段。

#### Scenario: 字段错误回填用户表单

- **WHEN** 新增或编辑用户收到带 `fieldErrors` 的 400
- **THEN** 测试 SHALL 证明字段错误和表单级 detail 均可见，抽屉不会自动关闭

#### Scenario: 无写权限只读操作

- **WHEN** 用户只有 `users:read`
- **THEN** 测试 SHALL 证明列表和详情可用，新增/编辑不可用，且不会请求角色分配目录

#### Scenario: 列表上下文改变清理选择

- **WHEN** 用户已选择表格行后改变筛选、排序或页大小
- **THEN** 测试 SHALL 证明旧行选择和相关批量操作上下文被清空

### Requirement: 设置和工作台恢复状态必须可验证

测试 SHALL 覆盖设置存储损坏回退、主题/语言/布局设置持久化与恢复默认值，以及 Dashboard 查询成功、空数据和可重试错误状态。纯展示组件不要求逐行覆盖。

#### Scenario: 设置存储损坏安全回退

- **WHEN** 本地设置包含非法 JSON 或不支持的枚举值
- **THEN** 测试 SHALL 证明应用使用安全默认设置并可继续渲染

#### Scenario: Dashboard 查询失败可重试

- **WHEN** Dashboard 查询返回网络、超时或 5xx
- **THEN** 测试 SHALL 证明页面显示错误和重试入口，不渲染为成功的业务数据
