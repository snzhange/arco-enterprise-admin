# Design

## Context

当前覆盖率已有全局门槛和 HTML/文本报告，但核心目录和正式页面的缺口会被总体均值掩盖。设计需要复用现有 Vitest/Istanbul 输出，增加稳定的目录配置、趋势摘要和 CI artifact，而不改变覆盖率工具的统计语义。

## Goals / Non-Goals

**Goals:**
- 为 `src/app`、`src/components`、正式支持页面目录声明可审查的目录级指标门槛。
- 生成包含基线差异的机器可读趋势摘要，并让 CI 在失败时保留报告。
- 防止通过扩大排除范围掩盖正式支持代码回退。

**Non-Goals:**
- 不追求一次性把所有页面提升到同一高门槛。
- 不把展示示例强行纳入正式业务门禁。

## Decisions

1. 采用仓库内版本化配置声明目录、指标和目标值，报告脚本读取 Vitest 的 JSON/LCOV 结果生成摘要；相比手工维护表格，机器生成能保证门禁与报告一致。
2. 以目录聚合 Lines、Statements、Branches、Functions，并保存最近一次可信基线；允许阈值用于渐进提升，但任何低于硬目标的回退都失败。
3. 正式支持页面分类来源于页面覆盖清单，示例页面单独标记并在摘要中展示；不通过全局 `exclude` 隐式隐藏。
4. CI 先运行单测和覆盖率，再运行门槛/趋势检查；无论成功或失败都上传 JSON、HTML、LCOV 和摘要。

## Risks / Trade-offs

- [目录移动造成历史趋势断裂] -> 配置使用稳定的逻辑范围并在变更中记录迁移映射。
- [小目录样本波动较大] -> 同时使用绝对目标和允许回退阈值，并在摘要中显示样本规模。
- [报告脚本与 Istanbul 格式耦合] -> 保留标准 JSON/LCOV 输入适配层并为解析器增加单测。

## Migration Plan

先生成当前覆盖率基线和目录摘要，以现有全局门槛为硬门禁；随后分阶段提高正式页面目录目标。若趋势检查误报，可回滚配置目标或阈值，不删除历史报告和分类信息。
